Carry the max, rescale the sum

Safe softmax reads a row of scores three times: once for the maximum, once for the sum, and once for the outputs. Online softmax gets the maximum m and the sum ℓ in one read. Each time a new block raises m, it multiplies the old ℓ by emold − mnew. FlashAttention applies the same factor to its partial output. Thus it reads each block of keys and values once and still computes exact attention.

Milakov & Gimelshein §2–3

Why softmax wants three passes

Softmax turns a row of scores x into weights that sum to 1: yi = exi / Σj exj. In attention, one row holds the scores of one query against all keys.

Take a score of 100. In 32-bit floats, e100 is infinity, because ex overflows for any x above approximately 88.72. Thus the plain formula fails on large scores.

The safe version subtracts the row maximum m first: yi = exi − m / Σj exj − m. The result does not change, and no exponent is above 0. But the sum needs m, and m needs a full read of the row. As a result, safe softmax reads the row three times. In 2018 the major frameworks used this version.

Online softmax merges the first two passes. It keeps a running max and a running sum, and it corrects the sum each time the max moves. The idea came from the one-pass algorithm for variance (Welford, 1962).

One rescale, by hand

Take one row with four scores in two blocks, [2, 1] and [4, 3]. Each key has one value: v = [10, 20, 30, 40]. The goal is the attention output O = Σ pi vi, where p is the softmax of the scores.

AfterRunning max mSum ℓ = Σ ex − mOutput O
block 1: [2, 1]2e⁰ + e⁻¹ = 1.3679(1·10 + 0.3679·20) / 1.3679 = 12.6894
block 2: [4, 3]max(2, 4) = 40.1353·1.3679 + (e⁰ + e⁻¹) = 1.5530(0.1353·1.3679·12.6894 + 1·30 + 0.3679·40) / 1.5530 = 30.3054
direct softmax, all four4e⁻² + e⁻³ + e⁰ + e⁻¹ = 1.55300.0871·10 + 0.0321·20 + 0.6439·30 + 0.2369·40 = 30.3054

Block 2 raised the max from 2 to 4. The weights of block 1 use the old max as their reference. Thus each one is too large by a factor of e². One multiplication by α = e2 − 4 = 0.1353 fixes all of them at once, together with their sum and their share of the output. The algorithm does not read block 1 again.

In general, the state (m, ℓ, O) after some blocks merges with a new block. The new block has its own max m̃, its own sum ℓ̃, and its own weights P̃ = ex − m̃:

mnew = max(m, m̃)
ℓnew = em − mnew ℓ + em̃ − mnew ℓ̃
Onew = ( em − mnew ℓ O + em̃ − mnew P̃V ) / ℓnew

These are lines 11 and 12 of FlashAttention's Algorithm 1. One of the two factors is always e⁰ = 1. The side that holds the larger max keeps its numbers, and only the other side shrinks. Line 12 divides O by ℓnew at every step. Thus O is always the softmax average of the values read up to that step. After block 1 above, 12.6894 is exactly the softmax of [2, 1] applied to [10, 20].

Why the order of blocks does not matter

Think of the pair (m, ℓ) as the number ℓ·em, written relative to m. A merge adds two of these numbers and writes the total relative to the larger max. Addition does not depend on order or grouping. Thus blocks can merge left to right, in reverse, or as a tree. Milakov & Gimelshein state this for their merge operator ⊕ and leave out the proof (§3.1). The simulator below checks it with numbers.

Why it stays safe

The running max m is always one of the scores. Thus it cannot overflow. No exponent is above 0, and as a result no weight is above 1. The sum ℓ stays between 1 and the number of scores read up to that point (Milakov & Gimelshein §3).

    FlashAttention Algorithm 1 · arXiv 2205.14135v2

    The same update, inside FlashAttention

    A GPU has two memories that matter here. HBM is the large memory off the chip. SRAM is the small memory on the chip, next to the compute units. On an A100, HBM holds 40–80 GB at 1.5–2.0 TB/s. Each of the 108 streaming multiprocessors has 192 KB of SRAM, with an estimated bandwidth of approximately 19 TB/s (FlashAttention §2.1).

    Standard attention writes the full N × N score matrix S and probability matrix P to HBM and reads them back (Algorithm 0). FlashAttention never stores them. It splits Q into blocks of Br rows and K, V into blocks of Bc rows. The SRAM size M and the head dimension d set both sizes: Bc = ⌈M/4d⌉ and Br = min(⌈M/4d⌉, d). For each pair of blocks, it computes S on chip. Then it runs the update from the worked example on every row of the block at once. It carries a running state from one K, V block to the next.

    Two details of Algorithm 1 shape the picture above. The outer loop runs over K, V blocks (line 5), and the inner loop runs over Q blocks (line 7). Thus each Q block's running state goes back to HBM after every step (lines 12–13). It returns at the next K, V block (line 8). Also, the state starts as O = 0, ℓ = 0 and m = −∞ (line 2). As a result, the first block needs no special case.

    The same two numbers help again in the backward pass. FlashAttention stores O and (m, ℓ) for each row. With them, it recomputes S and P block by block instead of storing them (§3.1). The result is exact: Algorithm 1 returns softmax(QKT)V with O(N²d) FLOPs and O(N) extra memory (Theorem 1). It needs Θ(N²d²/M) HBM accesses, against Θ(Nd + N²) for standard attention (Theorem 2). For typical head dimensions of 64–128 and M around 100 KB, d² is many times smaller than M.
